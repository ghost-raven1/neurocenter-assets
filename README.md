# neurocenter-assets

Versioned assets for Neurocenter and the shared `@neurocenter/asset-contract` producer/consumer package. MCP servers, OpenCode plugins, skills, models and the bridge keep their native installation formats.

The application flow is: provide a source → package → choose assets → import cards into the common catalog. Internal recipes, manifests and exact approval plans are generated by the server. Only genuine ambiguity or missing configuration needs a user choice. The developer commands below expose the contract; they are not a JSON-editing workflow for end users.

```sh
node bin/assets.mjs validate .
node bin/assets.mjs list .
node bin/assets.mjs preview . mcp-filesystem
node --test test/*.test.mjs
```

Requires Node.js 24+. No npm install, model download, DB connection or device installation is needed for these checks. The package supports ESM and Node 24 CommonJS `require`. Neurocenter must pin an exact repository commit when consuming it.

```js
import {createToolAsset, toToolPublication} from '@neurocenter/asset-contract';
const asset = createToolAsset(preparedBuildResult);
const nativePublication = toToolPublication(asset);
// The app runs its existing publication validator before persisting/importing.
```

The existing packager calls this producer after source detection and build. `neurocenter-assets export-tool prepared-input.json new-asset.json` is its lower-level, deterministic equivalent. It refuses conflicting runtime descriptors and never overwrites an existing output.

Read the [contract](skills/neurocenter-packaging/references/contract.md), [types](index.d.ts) and [packaging skill](skills/neurocenter-packaging/SKILL.md). Index and dependency hashes always cover exact descriptor bytes, including newlines. Tools declare runtime artifacts once; the consumer derives the native card configuration automatically.

The server fetches upstream files, verifies immutable storage and imports only selected cards with provenance. Computers download through the configured **API Gateway**, with the app's existing device/project permissions, SHA checks and approved plans. Public descriptors have no deployment gateway URL or credentials. Importing a card does not install it on a computer; a remote model also needs private server configuration before use.

The five initial assets use this single source format: MCP Filesystem, Git context plugin, Qwen3 Embedding 4B, bridge 0.9.10 and the packaging skill. Their pinned release URLs are server supply locations. The earlier release files are not a second catalog or an alternate import format. Both tool archives and both bridge payloads were checked against locally available bytes; the model lock and bundle passed native metadata validation, but model download and inference were not run.

`NOASSERTION` means license clearance has not been asserted. Before redistribution, preserve and verify the upstream license and notices. The Filesystem archive's metadata refers to a LICENSE file that was not present at the expected package path; importing its descriptor does not establish permission to redistribute that archive.

For an integration check against the app's actual source validators:

```sh
node bin/check-native.mjs ../neurocenter
```

This development check needs the app's catalog/skills dependencies installed. It performs tool producer → descriptor → native publication → verified package roundtrips, checks skill resources, model locks/bundles and native bridge release metadata, and verifies remote model metadata when supported. It does not mutate catalogs, start services or run tools/models. Live protocol/platform execution and inference remain separate checks.

This repository's original code currently has no redistribution license grant (`UNLICENSED`). Making the repository public does not change upstream licenses or grant rights to third-party runtime binaries.
